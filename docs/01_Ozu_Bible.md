# Ozu Bible

## 1. Introduction

### Purpose

Ozu exists to provide a modern manga reading platform with a cleaner, faster, and more enjoyable user experience than traditional manga websites. The project is designed with long-term maintainability and continuous improvement in mind.

### Vision

Ozu is a personal and open-source project that aims to demonstrate how a modern manga platform should be designed and developed. The project is intended to grow continuously while remaining accessible to the community.

### Mission

Ozu is committed to delivering a modern, minimalist, mobile-first, and high-performance reading experience. The platform prioritizes simplicity, speed, usability, and an uninterrupted reading experience while maintaining a clean and intuitive interface.



## 2. Core Principles

### Documentation First
Every significant decision must be documented before implementation.

### User Experience First
Every feature should contribute to a better reading experience.

### Mobile First
The platform is designed primarily for mobile devices while maintaining an excellent desktop experience.

### Performance Matters
Fast loading times, smooth navigation, and responsiveness are always priorities.

### Simplicity Over Complexity
Simple, maintainable, and scalable solutions are preferred over unnecessary complexity.

### Open Source Mindset
The project is developed transparently to encourage learning, collaboration, and community contributions.



## 3. Product Goals

### Modern Reading Platform
Build a modern manga reading platform.

### Reading Experience
Deliver a fast and intuitive reading experience.

### Personal Library
Provide an organized personal library for users.

### Responsive Design
Create a clean and responsive interface across all devices.

### Healthy Ecosystem
Build a healthy and sustainable ecosystem for manga readers.

### Maintainable Codebase
Maintain a scalable and maintainable codebase.

### Continuous Improvement
Continuously improve the platform through iterative development.



## 4. Target Audience

### Turkish Manga Readers
Ozu is primarily built for Turkish manga readers who want a modern, organized, and user-friendly reading platform.

### Mobile Users
The platform is designed primarily for mobile users while maintaining an excellent desktop experience.

### Personal Library Enthusiasts
Ozu is designed for readers who want to organize their favorite series, track their reading progress, and build a personal manga library.



## 5. Project Scope

### Manga Reading
Users can browse and read manga through a clean and modern reading interface.

### User Accounts
Users can create an account, manage their profile, and personalize their experience.

### Personal Library
Users can build and manage their own manga library, including favorites, reading lists, and reading progress.

### Search & Discovery
Users can search for manga and discover new series through filtering and categorization.

### Responsive Experience
The platform provides a consistent experience across mobile and desktop devices.

### Continuous Updates
The platform is designed to support continuous improvements and future feature expansions.



## 6. Out of Scope

### Anime Streaming
Ozu is not intended to provide anime streaming or video hosting services.

### Social Media Platform
Ozu is not designed to become a social media platform with feeds, posts, or similar features.

### News Platform
The project will not focus on anime or manga news publishing.

### Scanlation Group
Ozu is not a scanlation group and does not produce its own manga translations.

### Download Platform
The platform is not intended to provide downloadable manga archives.

### Marketplace
Ozu will never include a marketplace for buying, selling, or trading digital or physical goods.

### NFT & Blockchain Features
NFTs, cryptocurrencies, blockchain integrations, and similar Web3 features are permanently out of scope for the project.



## 7. Success Criteria

### Rich Manga Library
Users should always discover a wide variety of manga and feel excited about choosing what to read next.

### Community Interaction
Readers should be able to share opinions, discuss manga, and learn from the experiences and recommendations of other users.

### Memorable Experience
Every visit to Ozu should leave users with a positive impression, making them want to return again.

### User Satisfaction Over Numbers
Ozu measures success by the quality of the user experience, not by the number of users. Whether the platform has one user or one thousand, every user should feel that visiting Ozu was worth their time.



## 8. Release Strategy

### Milestone-Based Development
The development of Ozu is divided into five major milestones, each representing a significant stage in the project's lifecycle.

### GitHub Releases
Each completed milestone will be published as an official GitHub Release to preserve the project's development history.

### Semantic Versioning
Ozu follows the Semantic Versioning (SemVer) standard for version management.

### Continuous Delivery
The project is developed incrementally, with every completed feature being documented, committed, and pushed to GitHub before moving to the next task.



## 9. Naming Conventions

### File Naming
Documentation files use PascalCase with numeric prefixes when required.

Example:
- 00_Project_Decisions.md
- 01_Ozu_Bible.md

### Folder Naming
Folders use lowercase names.

Example:
- frontend
- backend
- database
- design
- docs

### Code Naming
Variables, functions, components, and other source code elements follow the conventions of their respective programming languages and frameworks.

### Consistency
Naming conventions should remain consistent throughout the entire project.
